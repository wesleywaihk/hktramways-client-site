Strapi Backend Setup Guide

Sets up a Strapi CMS inside backend/ using Docker for local dev (SQLite), ready to deploy to cloud (Postgres + S3) later.

WSL2 OpenSSL Issue: If you see ERR_SSL_CIPHER_OPERATION_FAILED during npm install, use:
npm install --registry http://registry.npmjs.org/
To install Node 18 via nvm: NVM_NODEJS_ORG_MIRROR=http://nodejs.org/dist nvm install 18

Step 1: Scaffold the Strapi App

Inside the backend/ directory, run the Strapi CLI to create a new project: 

cd backend
npx create-strapi-app@latest . --no-run

Choose these options when prompted:

  • Login/Sign up: Skip
  • Installation type: Custom
  • Database: SQLite (for local dev simplicity; you'll swap it per environment)
  • TypeScript: Yes (recommended)

Step 2: Add Docker for Local Development

Create backend/Dockerfile.dev:

FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 1337
CMD ["npm", "run", "develop"]

Create backend/docker-compose.yml:

services:
  strapi:
    build:
      context: .
      dockerfile: Dockerfile.dev
    ports:
      - "1337:1337"
    volumes:
      - .:/app
      - /app/node_modules
    environment:
      NODE_ENV: development
      DATABASE_CLIENT: sqlite
      DATABASE_FILENAME: .tmp/data.db
      APP_KEYS: "tobemodified1,tobemodified2"
      API_TOKEN_SALT: tobemodified
      ADMIN_JWT_SECRET: tobemodified
      JWT_SECRET: tobemodified

Then start it:

docker compose up

Step 3: Configure Environment-Based Database

Edit config/database.ts to read from env vars so you can swap SQLite (local) for Postgres (UAT/prod): 

export default ({ env }) => ({
  connection: {
    client: env('DATABASE_CLIENT', 'sqlite'),
    connection: {
      host: env('DATABASE_HOST', '127.0.0.1'),
      port: env.int('DATABASE_PORT', 5432),
      database: env('DATABASE_NAME', 'strapi'),
      user: env('DATABASE_USERNAME', 'strapi'),
      password: env('DATABASE_PASSWORD', ''),
      filename: env('DATABASE_FILENAME', '.tmp/data.db'),
    },
    useNullAsDefault: true,
  },
});

Step 4: Add S3 Upload Plugin

Install the provider:

npm install @strapi/provider-upload-aws-s3

Create config/plugins.ts:

export default ({ env }) => ({
  upload: {
    config: {
      provider: env('UPLOAD_PROVIDER', 'local'),
      ...(env('UPLOAD_PROVIDER') === 'aws-s3' && {
        providerOptions: {
          accessKeyId: env('AWS_ACCESS_KEY_ID'),
          secretAccessKey: env('AWS_ACCESS_SECRET'),
          region: env('AWS_REGION'),
          params: { Bucket: env('AWS_BUCKET') },
        },
      }),
    },
  },
});

Local dev leaves UPLOAD_PROVIDER unset (defaults to local). UAT/prod sets it to aws-s3.

Step 5: Create Environment Files

backend/
  .env                  ← local dev (SQLite, local uploads)
  .env.uat              ← UAT (Postgres, S3)
  .env.production       ← Production (Postgres, S3)
Add .env* to .gitignore. Commit .env.example with placeholder keys only.

Step 6: Production Dockerfile (for Cloud Deploy)

Create backend/Dockerfile:

FROM node:18-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:18-alpine
WORKDIR /app
COPY --from=build /app ./
EXPOSE 1337
CMD ["npm", "start"]

This image is what you push to your cloud provider (Railway, Render, Fly.io, ECS, etc.).

Step 7: Verify Local Setup Works

cd backend
docker compose up
# Open http://localhost:1337/admin

Complete the admin registration — if you see the Strapi dashboard, the local setup is done.

Environment Summary

Concern Local Dev UAT / Production
Database SQLite (file-based) Postgres (managed, e.g. RDS / Supabase)
File uploads Local disk AWS S3
Secrets .env Cloud env vars
Run command docker compose up Production Dockerfile

What's Next (Cloud Deploy)

  • Pick a cloud provider (Railway, Render, Fly.io, AWS ECS)
  • Set up a managed Postgres instance (RDS, Supabase, Neon)
  • Create S3 bucket + IAM user with least-privilege policy
  • Set UPLOAD_PROVIDER=aws-s3 and all AWS env vars in cloud dashboard
  • Build and push the production Docker image via CI/CD
